---
title: 本地工作区隔离导入
description: 将受支持的本地工作区导入独立平台目录的前置条件、数据处理和故障边界
---

平台提供离线维护命令 `--import-local-from`，把受支持的本地工作区复制到全新的平台目录，创建首个管理员并绑定原工作区。命令不会启动 HTTP 服务或任务 worker，也不会恢复历史上游执行。

这是一项有明确支持范围的阶段能力。它不接纳任意历史数据库，也不合并到已经有用户的平台实例。

## 执行前

1. 使用与源数据匹配的本地程序完成恢复，确认任务和文件操作结束，然后正常关闭程序及所有写入工具。
2. 另行保留源数据库、资源和 `.settings-key` 的一致备份。导入命令不会升级或清理源业务数据。
3. 确认源目录已经具有一致的 local 目录标记和数据库标记、唯一工作区，以及完整的规范本地 schema v29 迁移历史。
4. 为目标选择尚不存在的新目录，其父目录必须存在。源和目标不能相同或互相包含。
5. 准备管理员用户名、显示名、初始点数和存储上限。初始点数可以明确填 `0`；两个额度参数不能省略。

源目录在导入期间使用工作区锁。数据库以只读、不可变方式打开；非空 WAL 或回滚日志会被拒绝，避免忽略尚未合并的提交。不要手动删除数据库日志来绕过检查，应先由原程序恢复并正常关闭。

当前桌面入口、本地服务入口与导入命令共享工作区锁。Windows 还持有工作区旁的物理锁，防止不同系统账号绕过用户级发现锁；权限不足时导入失败，不会无锁继续。旧版本或其他数据库工具未必遵守这一锁合同，仍需按执行前要求停止全部写入者。

## 命令

在 `backend/` 构建平台程序：

```bash
go build -tags platform -o beeftv-platform ./cmd/platform
```

然后从交互终端执行，替换示例路径和显式额度：

```bash
./beeftv-platform \
  --import-local-from /srv/beeftv-local \
  --data-dir /srv/beeftv-platform-imported \
  --username administrator \
  --display-name 管理员 \
  --initial-points 0 \
  --storage-limit-bytes 10737418240
```

密码在终端隐藏输入并重复确认。不接受明文密码命令行参数或管道。导入不能与管理员初始化、备份、备份校验或恢复命令组合使用；导入成功后无需再执行管理员初始化。

导入会创建新账号 ID，但保留原 workspace ID，以及受支持的项目、章节、画布、素材、资源、任务、结果和关联 ID。平台账号与原工作区、初始点数发放和来源收据在同一事务中建立。

## 本阶段接受的数据

- 完整规范 schema v29，且表、字段、工作区归属和关联均通过审计。具有占用同一版本号的非规范预览分支历史时，停止导入。
- 本地 `ready` 资源；数据库引用、普通文件、相对存储键和文件字节数必须一致，资源必须能追溯到保留的业务对象。
- 已终结且无待查询、待交付或待结算状态的任务。成功媒体任务必须已经建立完整本地资源和素材关联。
- 受支持的画布工作流模板、版本及已终结运行；已有配方清理本地执行凭据后，用目标独立密钥重新加密。

数据库完整性、外键、必填父对象和复合项目关系都在复制前检查。未知表、字段、自定义触发器或视图、重复 JSON 键、未分类密文、无法解密的业务配置均会拒绝。

## 本阶段拒绝的数据

- 未完成任务、上游结果未知任务、活动工作流、上传预留、删除队列或进行中的转码。
- 外部对象存储资源、缺失文件、路径越界、源根链接、资源链接、具有多个硬链接的数据库主文件，以及被复制树内的特殊文件。
- 具有 `PlaybackObjectKey` 的播放缓存副本。当前尚无完整的平台副本容量及删除结算合同；可在源工作区按正常用户操作清理播放缓存后重试，原始媒体保留。
- 非空助手、提案、旧 Agent、技能、插件等尚未完成历史迁入审计的表；非空技能包、插件包、分片会话等未支持目录。
- 混合工作区归属、孤立关联、没有业务引用的资源、未知根文件或未识别的系统配置。

上述拒绝会停止整个导入，不自动丢弃历史模块。不要通过删除业务表或历史内容来强行满足条件；需要这些数据时，应等待对应导入支持或先评估独立迁移方案。

## 文件、凭据与容量

数据库通过 SQLite 一致快照进入隔离暂存目录。资源文件按清单复制并核对 SHA-256。导入前后比较被纳入清单的源业务文件，确认复制期间没有变化。

以下目录不复制，也不纳入一致性指纹：`cache`、`tmp`、`backups`、`diagnostics`、`support-traces`、`models`、`runtimes`、`downloads`、`skill-market`。这些目录内部不参与链接和特殊文件审计。运行描述文件、工作区锁文件和 SQLite SHM 也不参与业务指纹；获取工作区锁可能清理失效的运行描述文件。因此来源指纹表示受支持业务文件清单，不表示整个源目录树。

本地模型配置、参考存储配置、连接配置和本机令牌文件不会复制到平台。已知加密配置会先验证源密钥并提取可识别凭据用于残留审计。

本地渠道保留历史身份，但禁用渠道及模型并清除 Key、Header、上游地址与执行协议。任务和工作流执行材料清理后重新加密；历史调用日志的请求、响应和错误正文也会清空，身份、计数和状态保留。已识别源凭据出现在其他保留正文中时，整个导入被拒绝。

目标库开启安全删除并在净化后执行 `VACUUM`，交付前截断 WAL，避免被清理的明文凭据留在数据库空闲页。目标 `.settings-key` 独立生成，不复用源密钥。

资源对象按工作区与存储身份去重计量，建立已提交的存储记录。存量数据可以超过显式填写的上限；这不会删除数据，后续新增写入由平台额度合同拒绝，直到管理员提高上限或用户释放空间。

## 重复执行与故障

同一份来源再次导入同一个已完成目标时，返回原账号和工作区，不重复开户或发放点数。不同来源指纹、已有其他数据的目标或未完成目标会被拒绝。

所有迁移和净化先在暂存副本完成，源库不写入。开户或审计失败时不交付目标。最终交付把带有 `.platform-restore-incomplete` 的完整暂存目录原子改名到目标，使用 Windows、Linux 或 macOS 的禁止覆盖操作，避免替换并发创建的目录。发布后才移除阻断标记；不支持排他发布的系统会拒绝交付。

如果文件交付中断，半成品目标保留阻断标记并拒绝启动。不要手工删除标记来启动半成品；保留故障证据，选择另一个全新目录重新导入。进程异常终止也可能留下带阻断标记的暂存目录，应在确认无运行进程后由管理员处理。

导入完成后，使用平台程序打开目标目录，并配置平台渠道、价格和模型授权。历史任务保持只读；新的生成必须通过平台准入。首次导入不等于真实生成、公开部署或完整 P5 验收。
