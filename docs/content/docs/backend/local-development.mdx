# 本地开发

需要 Go（版本以 `backend/go.mod` 为准）、支持 CGO 的 C 编译器、Bun。媒体处理需要 FFmpeg 与 ffprobe。前端仅使用 `bun.lock`；不要混用其他包管理器。

## 初始化管理员

先生成预置模型协议包：Windows 运行 `scripts/build-protocol-packages.ps1`；Linux/macOS 运行 `plugin-packages/build-packages.sh`（需要 Node 和 zip）。容器构建自动执行此步骤。

在新的空数据目录中初始化一次：

```bash
cd backend
go run ./cmd/platform-admin --data-dir ../.local/platform-debug --username admin
```

密码在终端交互输入且不回显。原 `.local/project-workbench-debug` 属于单人工作区，不能用作平台目录，不会自动迁移或删除。

## 启动

Windows 可运行仓库根目录的 `scripts/start-local.ps1`。脚本检查端口后打开两个开发窗口，使用 `.local/platform-debug` 和 `.local/cache`。

手工启动后端：

```bash
cd backend
CANVAS_BACKEND_DATA_DIR=../.local/platform-debug \
CANVAS_PUBLIC_ORIGIN=http://localhost:3000 \
go run ./cmd/server
```

PowerShell 中使用环境变量赋值后启动：

```powershell
cd backend
$env:CANVAS_BACKEND_DATA_DIR = '../.local/platform-debug'
$env:CANVAS_PUBLIC_ORIGIN = 'http://localhost:3000'
go run ./cmd/server
```

另开终端启动前端：

```bash
cd web
bun install --frozen-lockfile
bun run dev
```

访问 `http://localhost:3000`。Vite 将 `/api` 转发到 `127.0.0.1:8080`；可用 `VITE_API_PROXY_TARGET` 修改代理目标。后端默认只监听回环地址。运行前确认端口与现有进程，避免误停其他服务。

Docker 热更新使用 `docker-compose.dev.yml`，启动前创建 `.local/platform-debug`、`.local/cache/go-build` 和 `.local/cache/go-mod`。源码镜像使用 `docker-compose.local.yml`；两者都使用独立平台存储。镜像包含预置模型协议与媒体工具，不包含助手宿主。

已经初始化的本地 Compose 部署，可使用 Node.js 运行以下脚本更新：

```powershell
node scripts/deploy-local.mjs
# 只构建和更新前端
node scripts/deploy-local.mjs web
```

脚本默认使用项目名 `beeftv-platform`；已有部署使用其他项目名时，必须通过 `--project-name` 指定相同名称以继续使用原数据卷。脚本等待服务健康后，只清理带该 Compose 项目标签、无标签且未被任何容器使用的旧镜像。数据卷、其他项目镜像与构建缓存不清理；构建或启动失败时保留旧镜像。直接执行 `docker compose build` 不会自动清理旧镜像。

## 验证

```bash
node scripts/structure-budget.mjs
node scripts/deadcode-budget.mjs
sh scripts/audit-public-docs.sh
cd backend
go test ./...
cd ../web
bun run typecheck
bun run lint
bun run build
```

SQLite 测试必须启用 CGO；仅编译通过不能替代数据库行为测试。账号与账本测试使用临时目录，不访问用户数据或付费模型。部署流程、恢复管理员与计费规则见[多用户平台](platform.mdx)。
