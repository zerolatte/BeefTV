# 平台备份与恢复

平台命令只处理已标记的平台目录；本地工作区导入是独立能力，不能通过复制目录并修改模式标记完成。平台仍处于开发验收阶段，备份工具可用不表示所有生成、工作流和部署验收已经完成。

## 迁移前自动备份

平台启动持有工作区实例锁，核对目录与数据库的双端模式标记，在启动任何业务写入服务之前检查本地及平台迁移版本。有待执行迁移时，先在平台目录同级的 `<目录名>.backups` 中创建完整备份，再进行迁移。备份失败会中止启动。空库第一次初始化不备份，当前版本再次启动不重复创建备份；高于程序支持版本的数据库直接拒绝启动。

每份备份包含：

- `data/open_ai_canvas.db`：通过 SQLite `VACUUM INTO` 创建并同步落盘的一致数据库副本。
- `data/.runtime-mode.json` 和 `data/.settings-key`：与数据库匹配的目录标记及主密钥。
- 资源、上传会话及其他数据目录普通文件。运行时描述、实例锁和源数据库 WAL/SHM 不复制。
- 最后写入的 `manifest.json`：备份格式、实例标识、迁移版本、创建时间及逐文件大小和 SHA-256 摘要。

复制期间源工作区必须停止写入。工具持有与平台进程相同的实例锁，拒绝从正在运行的平台创建离线备份；迁移前自动备份直接复用启动已经持有的锁。文件系统中的符号链接、目录联接和非普通文件会使备份失败。

SQLite 主文件具有多个硬链接时也会拒绝备份或恢复；不同目录中的硬链接可能仍共享同一份数据库，不能作为独立的可运行副本。

Windows 的平台进程与维护命令同时取得用户级发现锁和工作区旁的物理锁；使用不同系统账号执行维护也不能绕过正在运行的实例。账号需要具备对应目录和锁文件的访问权限，权限不足会直接失败，不会降级为无锁备份。停止服务后可保留锁文件，它不代表仍有进程持锁。

主密钥只在首次空库初始化时创建。已有数据库丢失主密钥会拒绝启动，应恢复匹配的备份，不能生成新密钥替代。

## 手动备份与校验

以下命令使用已按 `platform` 构建标签编译的程序，目录仅为部署示例；备份目标的父目录应已经存在，最终目标目录必须尚不存在。

```bash
./platform --data-dir /srv/beeftv-platform --backup-to /srv/backups/beeftv-before-upgrade
./platform --verify-backup /srv/backups/beeftv-before-upgrade
```

维护命令不启动 HTTP 服务，不要求 `--origin`。初始化、备份、校验、恢复和本地导入五种操作不能组合使用。校验会检查文件集合、大小、摘要、SQLite 完整性、主密钥与全部已有渠道凭据版本的解密匹配，以及目录和数据库的双端标记。就绪资源必须在当前数据目录内存在、为普通文件且大小与数据库一致；外部对象存储资源暂不支持完整备份。待上传、失败或删除中的资源按其持久状态保留。缺少完成清单、文件缺失、额外文件或内容损坏均拒绝恢复。摘要用于检测损坏，不是对不可信备份来源的签名认证。

备份包含完整业务数据及主密钥，应沿用数据目录的访问控制。工具新建目录使用 `0700`、普通文件使用 `0600`；备份仍应保存在受保护的卷中。

## 恢复与回退

```bash
./platform --restore-from /srv/backups/beeftv-before-upgrade --data-dir /srv/beeftv-restored
```

恢复先校验备份，再复制到全新目录，并重新核对目标文件摘要；不会覆盖旧目录，不执行迁移，不启动服务。目标目录会先写入 `.platform-restore-incomplete` 标记，全部检查、会话撤销和任务隔离成功后才移除；平台及本地启动预检遇到该标记都会拒绝打开，备份也拒绝把它作为有效数据源。核对成功后在目标数据库撤销旧会话，防止已经退出或撤销的登录因快照回退而复活。对于执行意图仍为 `reserved`、`submitting`、`accepted` 或 `unknown` 的任务，恢复会将意图隔离为 `unknown`、阻止排队或运行中的任务再次领取，并保留原点数预留，等待对照原数据目录及上游事实；旧快照不能证明原实例尚未发送请求。源备份保持不变。操作失败时清理本次创建的目标。

恢复在创建目标目录前先取得该路径的工作区锁，并保持到复制、核验、交付或失败清理全部结束。目标已存在或已被其他进程持锁时直接拒绝，不能删除对方目录；父目录的路径别名也使用同一锁身份。

停止原实例后，使用与备份迁移版本匹配的平台程序启动恢复目录，重新登录并验证资源读取、权限及账本。不要让旧本地程序打开平台数据库，不要删除迁移版本或降低版本号来模拟回退。恢复保留备份时的账号、任务及账本状态，会话全部失效；备份之后的业务变化不包含在恢复目录中，因此原数据目录应继续保留用于核对。

恢复也将快照中的排队、运行及额度暂停工作流标记为 `failed / backup_recovery_required`，保留步骤、成功结果和持久重试收据。旧快照不能证明原实例没有执行后续步骤，平台继续运行接口因此返回同名 409 原因，不能直接重试。已终结的工作流历史保持原状态；工作流状态 JSON 损坏会使恢复失败。

当前工具核验就绪资源文件与平台渠道凭据，不代替全部业务关联核对或上游执行结果对账。恢复后的未知任务不会自动重投或释放预留；需结合保留的原数据目录进行人工核对。

将本地工作区转换为平台目录应使用[本地工作区隔离导入](./platform-import)。该入口有独立的历史版本、归属和凭据净化审计，不能用恢复命令替代。
