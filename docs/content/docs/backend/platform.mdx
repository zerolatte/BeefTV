# 多用户平台

`cmd/server` 运行账号平台：单机 SQLite，每个账号拥有独立工作区。管理员负责开户、停用、重置临时密码、发布模型与发放积分；管理员不能读取其他用户的项目、画布、任务或素材。平台没有公开注册、团队共享、充值、人民币账务或周期额度。

## 初始化与部署

使用新的空目录或新的 `platform-data` 卷。启动器拒绝接管已有单人数据，不迁移、不清空原目录。数据目录由单进程锁保护，管理员恢复操作应先停止后端。

容器将卷挂载到 `/data`，实际数据目录为 `/data/platform`，工作区锁保存在卷根目录，确保非 root 用户能够正常获取锁。仅本机使用时可为以下命令统一加上 `-f docker-compose.local.yml`，该配置只绑定 `127.0.0.1:3000`。

```bash
docker compose build
docker compose run --rm -it backend platform-admin --data-dir /data/platform --username admin
docker compose up -d
```

初始化命令在终端交互读取密码且不回显，不通过命令行参数或环境变量传递密码。管理员登录后在“管理”页面创建账号，将只显示一次的临时密码交给账号使用者。首次登录必须改密。忘记管理员密码时：

```bash
docker compose stop backend
docker compose run --rm -it backend platform-admin --data-dir /data/platform --username admin --recover
docker compose up -d backend
```

本机默认来源为 `http://localhost:3000`。公网设置 `CANVAS_PUBLIC_ORIGIN=https://你的域名`，在前端入口配置 TLS；只暴露前端端口，后端 `8080` 留在容器网络中。浏览器与 API 必须同源，平台不开放跨域凭据访问。私网模型上游是否允许由 `CANVAS_ALLOW_PRIVATE_UPSTREAMS` 与精确主机白名单决定。公开部署建议使用根目录 `.env.example` 中的严格配置。

会话使用 HttpOnly Cookie，HTTPS 下启用 Secure，并使用 SameSite Strict；写请求同时校验来源、CSRF 和页面绑定的账号。会话有效期为 12 小时，退出、停用、改密和重置密码会使对应会话失效。已经建立的事件流会检查会话撤销。页面缓存按平台实例与账号隔离。

## 模型发布

管理员在“管理 → 模型”创建渠道，配置上游地址和密钥，再建立模型、能力配置和规格映射。每个启用规格必须有已发布积分价格，才允许用户生成。普通用户仅获得选型目录，不能保存自己的渠道、密钥或上游地址。

密钥在服务端配置中加密保存。不要把数据目录、SQLite、备份或 `.settings-key` 放到静态文件目录；它们需要限制访问权限，并共同纳入备份与恢复。用户提交的执行器、脚本、任意请求体、上游地址和密钥会被拒绝。内置助手、技能脚本、用户插件安装、外部 Agent 与旧模型代理接口在首版平台关闭。服务端预置模型协议继续复用现有实现。

## 积分语义

- 新账号为零积分，管理员可发放或收回整数积分；没有过期时间，不能收回已冻结的部分。
- 文本按调用计费，图片按张计费，视频和音频按结果计费；规格可分别定价。
- 每次新生成先取得有效期 5 分钟的报价，展示单价、单位数和冻结总额，由用户确认。
- 创建任务与冻结积分在同一个事务内完成。请求、模型配置或价格版本变化后，旧报价失效。
- 同一个用户提交标识最多创建一个任务；网络重试回读原任务，不再次冻结。
- 持久化有效产出后结算；确认无产出时退回。部分结果仍不确定时保留冻结，交由管理员依据上游记录核对。
- “继续取回”沿用原任务与冻结记录；已结算任务不能再领取上游恢复租约。重新生成必须创建新任务并确认新报价。
- 人工核对要求填写依据和有效产出数量；任务仍运行或持有有效恢复租约时禁止结算。账本保留冻结、消费、退款及管理员操作记录。

管理员用量页只展示任务编号、模型、数量和积分账目，不展示提示词、生成内容或素材。人工核对可以根据上游服务账目与任务编号进行；不能通过管理接口浏览用户创作内容。
